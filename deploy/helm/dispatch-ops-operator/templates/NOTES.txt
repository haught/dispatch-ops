The DispatchOps CRD was new to this cluster, so Helm couldn't create the

{{- if not (or .Values.installation.encryptionKey.key .Values.installation.encryptionKey.existingSecret) }}

The operator generates the encryption key in the
{{ .Values.installation.name }}-encryption-key Secret. Back it up: without it, stored
credentials can't be decrypted.
{{- end }}
{{- $tls := .Values.installation.tls | default dict }}
{{- if ne ($tls.enabled | toString) "false" }}

The API serves HTTPS on port 8443 ({{ .Values.installation.name }}-api Service).
{{- if $tls.existingSecret }} It serves the certificate in the {{ $tls.existingSecret }} Secret.
{{- else }} Its certificate is self-signed, generated in
the {{ .Values.installation.name }}-api-tls Secret; set installation.tls.existingSecret to
serve your own, such as a cert-manager Certificate's.
{{- end }}
{{- end }}
{{- if not .Values.installation.spec.admin }}

The administrator's password is in the {{ .Values.installation.name }}-admin-password Secret.
{{- end }}
{{- else }}

Create an installation, e.g. with an operator-managed database:

  kubectl apply -f - <<YAML
  apiVersion: dispatch-ops.io/v1alpha1
  kind: DispatchOps
  metadata:
    name: dispatch-ops
    namespace: dispatch-ops
  spec: {}
  YAML

or set installation.enabled in the chart's values. Follow it with
`kubectl get dispatchops -n dispatch-ops -w`. The administrator's password is
in the <name>-admin-password Secret.
{{- end }}
