The Dispatch Ops operator is running in {{ .Release.Namespace }}. It runs
{{ .Values.serverImage.repository }}:{{ .Values.serverImage.tag | default .Chart.AppVersion }} for DispatchOps resources that don't name an image.
{{- $ns := include "dispatch-ops-operator.installationNamespace" . }}
{{- $defaults := include "dispatch-ops-operator.defaultJobNamespaces" . | fromJson }}
{{- if .Values.watchAllNamespaces }}

It manages DispatchOps in every namespace, with cluster-wide permissions.
{{- else }}

It manages DispatchOps in {{ include "dispatch-ops-operator.watchNamespaces" . | fromJsonArray | join ", " }}.
{{- end }}
{{- if not .Values.allowJobNamespacesWithoutPodSecurity }}

Job namespaces must enforce Pod Security, or the operator won't run the task
manager there.
{{- if .Values.namespaces.create }} The chart labels the namespaces it creates; one that
existed before needs

  kubectl label namespace <namespace> pod-security.kubernetes.io/enforce=restricted
{{- else }} Label each:

  kubectl label namespace <namespace> pod-security.kubernetes.io/enforce=restricted
{{- end }}
{{- end }}
{{- if .Values.installation.enabled }}

It runs the installation {{ .Values.installation.name }} in {{ $ns }}
{{- with get $defaults $ns }}, with its jobs in {{ . }}{{ end }}. Follow it with

  kubectl get dispatchops -n {{ $ns }} -w
{{- if not (or .Values.installation.encryptionKey.key .Values.installation.encryptionKey.existingSecret) }}

The operator generates the encryption key in the
{{ .Values.installation.name }}-encryption-key Secret. Back it up: without it, stored
credentials can't be decrypted.
{{- end }}
{{- $tls := .Values.installation.tls | default dict }}
{{- if ne ($tls.enabled | toString) "false" }}

The API serves HTTPS on port 8443 ({{ .Values.installation.name }}-api Service).
{{- if $tls.existingSecret }} It serves the certificate in the {{ $tls.existingSecret }} Secret.
{{- else }} Its certificate is self-signed, generated in
the {{ .Values.installation.name }}-api-tls Secret; set installation.tls.existingSecret to
serve your own, such as a cert-manager Certificate's.
{{- end }}
{{- end }}
{{- if not .Values.installation.spec.admin }}

The administrator's password is in the {{ .Values.installation.name }}-admin-password Secret:

  kubectl -n {{ $ns }} get secret {{ .Values.installation.name }}-admin-password -o jsonpath='{.data.password}' | base64 -d
{{- end }}
{{- else }}

Create an installation, e.g. with an operator-managed database:

  kubectl apply -f - <<YAML
  apiVersion: dispatch-ops.io/v1alpha1
  kind: DispatchOps
  metadata:
    name: dispatch-ops
    namespace: {{ $ns }}
  spec: {}
  YAML

Follow it with `kubectl get dispatchops -n {{ $ns }} -w`. The administrator's
password is in the <name>-admin-password Secret.
{{- end }}
